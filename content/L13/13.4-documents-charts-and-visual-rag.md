# Documents, charts and visual RAG

A huge share of business AI work is documents: invoices, contracts, statements, forms, reports full of tables and
charts. Text-only RAG treats them as clean text. Real documents are scans, multi-column layouts and tables that break
across pages. This lesson covers reading them, extracting validated fields, and retrieving over pages as images.

## Text layer or scan

First question for any PDF: does it carry a text layer?

```python
import fitz  # PyMuPDF

doc = fitz.open("statement.pdf")
for page in doc:
    text = page.get_text()
    print(page.number, "text" if len(text.strip()) > 50 else "probably a scan")
```

A digital PDF exported from software has real characters you can extract exactly and cheaply. A scan or phone photo is
only pixels; every character must be recovered by OCR or a vision model, with errors.

## OCR vs vision reading

| | Classic OCR / layout tools | Multimodal model reading the page |
|---|---|---|
| Accuracy on clean print | Very high | Very high |
| Handwriting, stamps, odd layouts | Weak to fair | Usually better |
| Layout and reading order | Needs a layout model | Often handled implicitly |
| Cost and latency | Low, predictable | Higher: page images are many tokens |
| Failure style | Garbled characters you can see | Fluent, plausible, sometimes invented |

A common production pattern: use the text layer when present, OCR or a document-AI service for scans, and a vision
model only for pages or regions where those fail.

## Layout, tables and charts

Flattening a page into one text stream is where meaning dies:

- **Reading order**: two columns read straight across produce interleaved nonsense. Headers, footers and sidebars get
  spliced into paragraphs.
- **Tables**: merged cells, multi-page tables (header only on page 1), and key-value forms where "Total due" sits far
  from its number.
- **Checkboxes**: the tick is a visual mark with no text at all.
- **Charts**: a model reads axis labels, legend and any printed numbers. Values without labels are estimated from bar
  heights. Never store a chart-read number as exact unless it was printed.

## Schema-first extraction

Decide what you need before you write the prompt. A schema makes the output checkable:

```python
from pydantic import BaseModel, Field, field_validator
from datetime import date

class Invoice(BaseModel):
    invoice_number: str
    invoice_date: date
    currency: str = Field(pattern=r"^[A-Z]{3}$")
    line_totals: list[float]
    total: float
    total_page: int          # grounding: where the value was found

    @field_validator("total")
    @classmethod
    def positive(cls, v: float) -> float:
        if v <= 0:
            raise ValueError("total must be positive")
        return v

def check(inv: Invoice) -> list[str]:
    issues = []
    if abs(sum(inv.line_totals) - inv.total) > 0.01:
        issues.append("line items do not sum to total")
    if inv.invoice_date > date.today():
        issues.append("invoice dated in the future")
    return issues
```

Pass the schema to the model's structured-output feature, parse into the Pydantic model, then run business checks.
Types catch formatting errors; cross-field checks (sums, dates, units) catch misreads.

## Grounding and review

Ask for the page number (or a bounding region, if the model supports it) of each field. A reviewer can then jump to
the exact spot instead of re-reading 20 pages.

Document-specific failures to plan for:

- Values invented for **blank cells**.
- **Rows merged** across a page break.
- Confused **units or currencies** (thousands vs units, USD vs INR).
- Misread **handwriting**.

Route anything that fails validation, has low confidence, or is above a value threshold to a human queue. An
uncertain value silently written to a database is worse than a flagged one.

## Visual RAG

Instead of chunking extracted text, you can make the **page image** (or a region) the retrieval unit:

- Embed page images with a vision-language retriever. ColPali-style models produce many vectors per page (one per
  patch) and match them against query tokens with late interaction, so they can find a page by its chart or table
  without OCR.
- Retrieve top pages, send those images to a multimodal model, and cite the page number in the answer.
- Hybrid: search extracted text and page images in parallel and fuse the rankings. Text wins for exact terms and
  clean prose; images win for charts, diagrams and complex layouts.

Cost check: a page as text might be 500 tokens; the same page as a high-detail image might be 1,500 or more. Five
retrieved pages per query is then ~2,500 vs ~7,500 input tokens. For clean digital text, page images rarely earn their
cost. Use them where layout carries the meaning.

## Try it

Take one scanned invoice and one digital PDF invoice. Run each through (a) text extraction or OCR plus a text LLM, and
(b) a vision model on the page image, both extracting the same four fields into a schema. Compare accuracy, tokens and
latency.

<details>
<summary>Reference</summary>

Digital PDF: the text pipeline is as accurate, several times cheaper and faster. Scan: plain OCR plus text LLM usually
loses table structure and may misassign line items; the vision pipeline is more accurate on layout but costs more,
and may invent a value where the scan is faint. Validation (line items summing to the total) catches most errors in
both. Conclusion: route by document type.
</details>

## Check yourself

1. Why should you check for a text layer before sending a PDF to a vision model?

<details>
<summary>Answer</summary>

A text layer gives exact characters cheaply and quickly. Sending page images costs many more tokens and introduces
recognition errors that the text layer would not have.
</details>

2. Your extraction returns valid JSON that passes the schema, but the total is wrong. Which check would catch it?

<details>
<summary>Answer</summary>

A cross-field business check, such as recomputing the sum of line items and comparing it to the total, or checking
the total against a known range. Schemas only check types and formats.
</details>

3. When does visual RAG beat text RAG, and when is it wasteful?

<details>
<summary>Answer</summary>

It wins when meaning lives in layout: charts, diagrams, complex tables, scans with poor OCR. It is wasteful for clean
digital prose, where text retrieval is just as accurate at a fraction of the tokens and latency.
</details>
