# Serving and containers

A notebook is not a service. To put your RAG app and agent in front of users you need a backend with a real API, a
frontend that only draws the interface, and containers so the whole thing runs the same on your laptop, in CI and in
the cloud. This lesson builds that stack.

## A FastAPI backend

Move the app logic into a FastAPI service. Requests and responses get Pydantic models, so bad input is rejected with a
clear 422 before it costs a token.

```python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse, JSONResponse
from pydantic import BaseModel, Field
import asyncio, json

app = FastAPI()

class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=4000)
    session_id: str | None = None

@app.post("/ask/stream")
async def ask_stream(body: AskRequest, request: Request):
    async def events():
        try:
            async with asyncio.timeout(60):                      # hard cap per request
                async for token in rag_stream(body.question):     # yields text deltas
                    if await request.is_disconnected():
                        break                                     # stop paying for tokens nobody reads
                    yield f"data: {json.dumps({'delta': token})}\n\n"
            yield "event: done\ndata: {}\n\n"
        except TimeoutError:
            yield f"event: error\ndata: {json.dumps({'message': 'timed out'})}\n\n"
        except GuardrailBlocked as e:
            yield f"event: error\ndata: {json.dumps({'message': str(e)})}\n\n"
    return StreamingResponse(events(), media_type="text/event-stream")
```

**Server-sent events (SSE)** are a plain HTTP response that stays open and sends `data:` lines. They are simpler than
WebSockets and enough for one-way token streaming. Breaking out of the loop when the client disconnects matters: if
your provider stream is closed when the generator ends, you stop paying for output nobody will read.

## Health and readiness

Load balancers and orchestrators need to ask "are you alive?" and "can you serve?". These are different questions.

```python
@app.get("/healthz")
async def healthz():
    return {"status": "ok"}             # process is up

@app.get("/readyz")
async def readyz():
    checks = {"vector_db": await ping_vector_db(), "llm_provider": await ping_provider()}
    status = 200 if all(checks.values()) else 503
    return JSONResponse(checks, status_code=status)
```

Keep the provider check cheap (a models-list call or a cached result from the last real request), not a full
generation every few seconds.

## A thin Streamlit frontend

The frontend holds no prompts, no retrieval and no keys. It calls the backend and renders what comes back.

```python
import json, requests, streamlit as st

st.title("Support assistant")
q = st.chat_input("Ask a question")
if q:
    with st.chat_message("assistant"):
        def tokens():
            with requests.post(f"{API}/ask/stream", json={"question": q}, stream=True, timeout=90) as r:
                for line in r.iter_lines(decode_unicode=True):
                    if line.startswith("data: "):
                        payload = json.loads(line[6:])
                        if "delta" in payload:
                            yield payload["delta"]
                        elif "message" in payload:
                            yield f"\n\nSorry, something went wrong: {payload['message']}"
        st.write_stream(tokens())
```

Errors, timeouts and guardrail blocks should reach the user as plain sentences, never as a stack trace.

## Docker images

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.lock .
RUN pip install --no-cache-dir -r requirements.lock
COPY app/ app/
COPY config/ config/
USER 1000
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Copy the lock file before the source so dependency layers are cached between builds. Pin the base image tag. Run as a
non-root user. There is no API key anywhere in this file.

## The stack in Compose

```yaml
services:
  api:
    build: ./backend
    env_file: .env            # OPENAI_API_KEY, LANGFUSE_*, etc. Not committed.
    environment:
      APP_CONFIG: config/rag.yaml
      QDRANT_URL: http://qdrant:6333
    depends_on: [qdrant]
    ports: ["8000:8000"]
  ui:
    build: ./frontend
    environment:
      API_URL: http://api:8000
    ports: ["8501:8501"]
  qdrant:
    image: qdrant/qdrant:v1.12.0   # example pinned tag
    volumes: ["qdrant_data:/qdrant/storage"]
volumes:
  qdrant_data:
```

**Secrets at runtime, not build time.** Anything in an image layer can be extracted by anyone who can pull the image,
even if a later layer deletes it. Pass keys as environment variables (from `.env` locally, from a secrets manager in
the cloud) and add `.env` to both `.gitignore` and `.dockerignore`.

## Try it

On a clean machine (or a fresh clone), start the whole stack with one command and confirm streaming works end to end.

<details>
<summary>Reference</summary>

`git clone … && cp .env.example .env` (fill in keys) `&& docker compose up --build`. Open the Streamlit UI, ask a
question, and watch tokens appear gradually rather than all at once. If the answer arrives in one lump, something is
buffering: check that the backend yields per token, that the frontend uses `stream=True`, and that no proxy in between
buffers responses. Then close the browser tab mid-answer and confirm in the backend logs that generation stopped.
</details>

## Check yourself

1. Why check `request.is_disconnected()` inside the streaming loop?

<details>
<summary>Answer</summary>

So that when a user leaves, the server stops generating and closes the provider stream, instead of paying for output
tokens nobody will see.
</details>

2. What is the difference between a health check and a readiness check?

<details>
<summary>Answer</summary>

Health says the process is alive. Readiness says it can actually serve, meaning its dependencies (vector DB, model
provider) are reachable. A load balancer should only send traffic to ready instances.
</details>

3. Why is putting an API key in a Dockerfile `ENV` line dangerous even for a private registry?

<details>
<summary>Answer</summary>

It is stored in the image metadata and layers, so anyone who can pull or inspect the image can read it, and it lives
on in every copy and cache. Keys should be injected at runtime.
</details>
