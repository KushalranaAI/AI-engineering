# Building APIs with FastAPI

Most AI features ship behind an HTTP endpoint. FastAPI is the common Python choice because it turns type hints into
validation, serialisation and interactive docs with almost no extra code.

## Routes, parameters and models

```python
# app/main.py
from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel, Field

app = FastAPI(title="Bookmarks")

class BookmarkIn(BaseModel):
    url: str
    title: str = Field(min_length=1, max_length=200)
    tags: list[str] = []

class BookmarkOut(BookmarkIn):
    id: int

DB: dict[int, BookmarkOut] = {}

@app.post("/bookmarks", response_model=BookmarkOut, status_code=status.HTTP_201_CREATED)
def create(b: BookmarkIn) -> BookmarkOut:
    new = BookmarkOut(id=len(DB) + 1, **b.model_dump())
    DB[new.id] = new
    return new

@app.get("/bookmarks/{bookmark_id}", response_model=BookmarkOut)
def read(bookmark_id: int) -> BookmarkOut:
    if bookmark_id not in DB:
        raise HTTPException(status_code=404, detail="Bookmark not found")
    return DB[bookmark_id]

@app.get("/bookmarks", response_model=list[BookmarkOut])
def list_(tag: str | None = None, limit: int = 20) -> list[BookmarkOut]:
    items = [b for b in DB.values() if tag is None or tag in b.tags]
    return items[:limit]
```

Run it with `uv run fastapi dev app/main.py` and open `/docs`. FastAPI reads the signatures: `bookmark_id` in the
path is a path parameter, `tag` and `limit` are query parameters, and `b: BookmarkIn` is the JSON body. Bad input gets
an automatic 422 with a description of what failed. `response_model` filters and shapes the output, so you never leak
fields by accident.

## Generated docs

`/docs` (Swagger UI) and `/openapi.json` are built from your models and signatures. That schema is a contract: client
generators, API gateways and, later, LLM tool definitions can all be derived from it. Good field names and
`description=` text pay off twice.

## Dependencies

Dependency injection lets endpoints declare what they need, and FastAPI provides it per request:

```python
from typing import Annotated
from fastapi import Depends, Header

def require_key(x_api_key: Annotated[str, Header()]) -> str:
    if x_api_key != settings.api_key:
        raise HTTPException(status_code=401, detail="Invalid API key")
    return x_api_key

@app.delete("/bookmarks/{bookmark_id}", status_code=204, dependencies=[Depends(require_key)])
def delete(bookmark_id: int) -> None:
    DB.pop(bookmark_id, None)
```

Typical dependencies: settings, a database session, the current user. In tests you can swap them with
`app.dependency_overrides`.

## Errors clients can use

Pick one error shape and stick to it. Raise `HTTPException` for expected cases, and add a catch-all handler so
unexpected exceptions become a clean 500 instead of a stack trace:

```python
import logging
from fastapi import Request
from fastapi.responses import JSONResponse

log = logging.getLogger("app")

@app.exception_handler(Exception)
async def unhandled(request: Request, exc: Exception) -> JSONResponse:
    log.exception("unhandled error on %s", request.url.path)
    return JSONResponse(status_code=500, content={"detail": "Internal server error"})
```

## Sync vs async endpoints

| Write | When | Why |
|-------|------|-----|
| `def` | calling blocking libraries (many DB drivers, `requests`) | FastAPI runs it in a thread pool |
| `async def` | awaiting async clients (`httpx.AsyncClient`, async DB drivers) | runs on the event loop, scales to many waits |

The bug to avoid: a blocking call inside `async def` freezes every request on that worker. Calling an outside
service correctly looks like this:

```python
import httpx

@app.get("/preview")
async def preview(url: str) -> dict:
    async with httpx.AsyncClient(timeout=5) as client:
        try:
            r = await client.get(url)
        except httpx.HTTPError:
            raise HTTPException(status_code=502, detail="Upstream fetch failed")
    return {"status": r.status_code, "bytes": len(r.content)}
```

## Config, lifespan and middleware

Load configuration from environment variables (for example with `pydantic-settings`). Use a `lifespan` function to
create shared resources such as an HTTP client or database pool at startup and close them at shutdown. Middleware wraps
every request: logging, timing, CORS, request ids.

## Testing

```python
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_create_and_read():
    r = client.post("/bookmarks", json={"url": "https://x.dev", "title": "X"})
    assert r.status_code == 201
    assert client.get(f"/bookmarks/{r.json()['id']}").json()["title"] == "X"

def test_validation():
    assert client.post("/bookmarks", json={"url": "https://x.dev", "title": ""}).status_code == 422
```

## Check yourself

1. What does FastAPI return when a request body fails Pydantic validation, and why is that useful?

<details>
<summary>Answer</summary>

A 422 response listing each failing field and why. Clients get a precise, machine-readable error and your handler
never runs with bad data.
</details>

2. Why is `time.sleep(2)` inside an `async def` endpoint worse than inside a `def` endpoint?

<details>
<summary>Answer</summary>

`async def` runs on the event loop, so a blocking sleep stalls every concurrent request on that worker. A `def`
endpoint runs in a thread pool, so it only ties up one thread.
</details>

3. Name two things that belong in a dependency rather than in each endpoint.

<details>
<summary>Answer</summary>

Examples: loading settings, opening a database session, authenticating the caller, rate-limit checks. Anything shared
and replaceable in tests.
</details>
