# RAG metrics: faithfulness, relevancy, precision, recall, correctness

A RAG answer can fail in different places: the retriever missed the evidence, the evidence was buried under noise, the
model ignored the evidence, or the model answered a different question. One "accuracy" number cannot tell these apart.
Five metrics, popularised by the Ragas framework, each isolate one failure. This lesson defines them precisely, works
one example by hand, and shows how to read them together.

The names and exact formulas vary slightly between libraries and versions, so check the documentation of the one you
use. The ideas below are stable.

## The example

**Question:** "What is the refund window for laptops, and is a fee charged?"
**Reference answer:** "Laptops can be returned within 15 days; opened items incur a 10% restocking fee."
**Retrieved chunks (in order):** (1) a shipping-times article, (2) the returns policy for electronics ("15 days; opened
items 10% fee"), (3) a warranty article.
**Model answer:** "Laptops can be returned within 15 days. A 10% fee applies if opened. Returns are free of shipping
charges."

## Faithfulness: is the answer supported by the context?

Split the answer into **claims** and check each against the retrieved context.

- "Laptops can be returned within 15 days" → supported.
- "A 10% fee applies if opened" → supported.
- "Returns are free of shipping charges" → not in the context.

**Faithfulness = supported claims / total claims = 2/3 ≈ 0.67.** This is your hallucination detector. It needs only the
question, the context and the answer, no reference.

## Answer relevancy: does the answer address the question?

The metric asks a model to generate questions that the answer would respond to, embeds them, and measures their
similarity to the original question. An answer that rambles, or answers a neighbouring question, scores low. It says
nothing about truth: a wrong answer to the right question can score high. Pair it with faithfulness.

## Context precision: is the useful context ranked first?

Look at the retrieved chunks in order and mark each relevant (R) or not (N): here **N, R, N**. Precision at each rank where
a relevant chunk appears is averaged:

- rank 2 is relevant; precision@2 = 1 relevant / 2 retrieved = 0.5.
- Average over relevant ranks = 0.5.

**Context precision = 0.5.** Had the policy been first (R, N, N), it would be 1.0. Low precision means noise (and a
missing reranker, 4.11) is crowding the prompt.

## Context recall: did we retrieve everything needed?

Split the **reference answer** into claims and ask whether each can be found in the retrieved context. Both claims (15 days;
10% fee) appear in chunk 2, so **context recall = 2/2 = 1.0**. If the fee were stored in a chunk that was not retrieved,
recall would be 0.5. Low recall means the retriever (or chunking, or the query rewrite) is missing evidence, and no prompt
change will fix that.

## Answer correctness: is the answer right?

Compare the answer with the reference. Ragas blends **factual overlap** (claims in common, scored as an F1 against the
reference) with **semantic similarity** of the two texts, with default weights of roughly 0.75 and 0.25. Our answer matches
both reference claims but adds an extra one, so factual precision is 2/3 and recall 2/2, giving F1 = 0.8; with a high
similarity score the final value would be around 0.85. It needs a reference, so it only works with a golden set (7.7).

## Reading the metrics together

| Faithfulness | Answer relevancy | Context precision | Context recall | Likely fault | Fix |
|--------------|------------------|-------------------|----------------|--------------|-----|
| low | high | high | high | model ignores or adds to good context | tighten the grounding prompt (4.13), lower temperature |
| high | high | high | **low** | evidence not retrieved | better chunking, hybrid search, query rewriting |
| high | high | **low** | high | right chunk retrieved but buried | add reranking, lower top-k |
| high | **low** | any | any | answers the wrong question | prompt or query-understanding fix |
| all high, correctness low | | | | reference or labelling problem, or reasoning error | review the golden case |

Our example (faithfulness 0.67, precision 0.5, recall 1.0) points to two fixes: a stricter "only from context" prompt,
and a reranker so the returns policy comes first.

## Metrics are estimates

Each score depends on a judge model and an embedding model, so it carries noise. Fix the judge and its prompts across runs,
report averages over the whole set with intervals (7.8), and look at the lowest-scoring individual rows, not just means.
A change from 0.81 to 0.83 on 60 questions is probably not real.

## Try it

For a question about visa rules, the retriever returned five chunks, with the one relevant chunk at rank 4. The answer was
fully supported by the context but ignored half of what the reference says. Predict which metrics are low.

<details>
<summary>Reference</summary>

Context precision is low (the only relevant chunk is fourth: precision@4 = 1/4 = 0.25). Faithfulness is high (everything
claimed is supported). Context recall is likely low or middling if the missing half of the reference was not in the
retrieved chunks, and answer correctness is low because the answer is incomplete. Fix retrieval ordering (reranking) and
check whether the missing facts were retrieved at all.
</details>

## Check yourself

1. Which metric detects hallucination, and what does it need as input?

<details>
<summary>Answer</summary>

Faithfulness. It needs the question, the retrieved context and the answer; it checks whether each claim in the answer is
supported by the context.
</details>

2. Context recall is low but faithfulness is high. Where is the problem?

<details>
<summary>Answer</summary>

In retrieval: the needed evidence was not retrieved, and the model stayed faithful to what it had. Improve chunking,
search or query rewriting rather than the generation prompt.
</details>

3. Why does answer relevancy not prove an answer is correct?

<details>
<summary>Answer</summary>

It measures whether the answer addresses the question asked, not whether it is true. A fluent wrong answer can score high.
</details>
